# Player state schema v1 (race scenario)

Validated in [M1-02](../../tasks/M1-02.md); evidence in [R-0007](../research/R-0007-player-state.md). Scope: the single-player race of `race-crawler-dragster-3000` (MIKE vs BRONSEN on DRAGSTER, Crawler tour) on the PAL ROM under the pinned bsnes core. Addresses are work RAM offsets in bank `$7E` (the game reaches them through the `$00:0000–$1FFF` mirror, so the writers below store to `$00:xxxx`); the same declarations are `tests/manifests/fields/player-state-v1.json` and are used by `tests/manifests/replay/race-crawler-dragster-3000-fields.json`. One game update is one PAL frame (every writer below executes exactly once per frame over the riding phase; R-0007 finding 9). The sample point is the end of `retro_run` (R-0003), after the whole update; the value sampled at the end of frame N reflects the inputs presented for frame N (finding 10).

## Unknown or not found

- **Lean or tilt.** Up versus Down while riding (2200–2259) differ in exactly two bytes of the whole 128 KiB work RAM at the end of frame 2230 (`$0313`, `$0315`) and the final states are identical; the visible tilt (R-0006 finding 8) is not backed by a persistent work RAM state in this scenario. Recorded as unknown (probably sprite selection from `axis_v` each frame).
- **Y.** With Y held from 1500 the rider never leaves the start line (`pos_x` = 1088, `speed` = 0 while `throttle` saturates at 432 from frame 1500 instead of 1503) and 261 bytes differ by frame 1560; the mechanism is not interpreted.
- **L, R.** Each sets one byte (`$0329`, `$032D`) to 1 at 1500 and changes nothing else in the sampled range through frame 1599.
- **Opponent AI** beyond its position instance; the rider's y coordinate, angle and animation state; the meaning of `$0400`–`$0403` (wheel/angle accumulators changing by fixed steps).
