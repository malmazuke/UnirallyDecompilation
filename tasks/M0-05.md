## Outcome and boundaries

Demonstrate that the process, not the conversation, carries the work: a fresh session reproduces the M0-04 baseline from `docs/STATE.md`, `AGENTS.md` and the M0-04 handoff alone, then completes a bounded follow-up that the M0-04 reviewers left as a note: a ROM-free test of `replay compare`'s post-run wiring (`fresh_processes`, the required/optional `av_identical` rule, optional localization runs, the divergence report and exit codes) with a stubbed worker, so those paths are regression-safe without the ROM. Exercise interrupted-run recovery (a `replay compare` killed while a worker runs, then re-run from the handoff: no partial artifact may be mistaken for a result) and failed-test reporting (a deliberately failing test in a scratch worktree must make `test --suite synthetic` exit 1 and name the failing record; never a pass). Submit for independent review, then verify the exact candidate. Record the process gaps found before two workers are allowed to run concurrently.

Not in scope: a scheduler (a coordinator and durable records suffice), gameplay work (M1), native code, changes to the reference or replay formats.

## Process gaps observed

Full table with evidence and suggested handling in [R-0004](../docs/research/R-0004-resumable-execution.md). Summary for the coordinator's concurrency decision:

| ID | Gap | Blocks a second worker? |
| --- | --- | --- |
| G1 | `tasks/README.md` still shows M0-05 as `ready: … not claimed` while this record says `claimed`; two coordinator-owned files carry the same fact | Yes — a stale registry row is how one task gets dispatched twice |
| G2 | A worker survives the death of its parent (it is started in its own session) and keeps running the core, writing into the parent's artifacts directory afterwards | Yes for reassignment: check for live `reference/worker.py` processes before reassigning a task whose heartbeat is stale |
| G3 | An explicit `--artifacts` directory is never cleaned, so a stale `divergence.json` or an orphan's samples sit beside a later passing run's files | No — the report, not the directory, is the result; give each attempt its own path |
| G4 | Heartbeat and checkpoint are prose in the task record; a checkpoint is only visible as a commit, and nothing records that a worker is alive between commits | Yes for a shared queue: the workflow's atomic claims and lease store should exist before two workers are dispatched from it |
| G5 | The handoff does not state runtime needs (network for the pinned wheels and the core clone, ~15 s of core build, the fixture arrangement) | No — add a "runtime needs" line to the handoff template |
| G6 | Without `--against`, localization re-runs execute the same manifest on both sides, so a divergence between repetitions is not reproduced and the work RAM diff is empty while `divergence_localized` passes | No — the verdict comes from the required field comparison; worth a note in the check's detail |
| G7 | CI is ROM-free, so no automated check covers a command that needs the core | No — known and accepted for M0; the stubbed-worker tests narrow it |
