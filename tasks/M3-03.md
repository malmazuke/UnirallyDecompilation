## Outcome and boundaries

Provide the smallest maintainable SDL3 desktop program that runs the accepted
CRAWLER/DRAGSTER native slice. It validates and consumes the Classic pack,
advances the native simulation at PAL 50 Hz, samples keyboard or one gamepad
into the existing two-controller input masks once per update, and displays the
accepted 256x224 presentation with deterministic integer scaling.

On first launch, absence of a valid pack leads to an explicit supported-ROM
selection/argument flow, exact ROM identity verification and atomic local pack
creation. Once created, the same application must relaunch from the pack with
the ROM removed. Cancel, missing ROM, wrong ROM, corrupt pack, renderer failure
and SDL failure must not become successful launches. Audio is intentionally
absent in M3 and must be declared in help/about/startup output.

Not in scope: menus beyond the minimal launch/error flow, audio implementation,
other tracks/riders/modes, interpolation that affects simulation, remapping UI,
configuration persistence beyond the pack path, packaging/release publishing,
online play or original CPU execution. M3-04 owns real sustained-play and
clean-checkout milestone acceptance.

## Required contract freeze

Before UI implementation, record and test:

1. The SDL3 version/source/checksum and local, non-global build arrangement on
   macOS and Linux; headless core/test builds must remain window-independent.
2. The exact 50 Hz monotonic-clock scheduler: maximum catch-up work, pause/
   resume behavior and how delayed display frames affect input/update/render.
3. Keyboard/gamepad button mapping to the accepted SNES masks, including
   simultaneous buttons, release, disconnect and focus loss.
4. The application pack path, explicit ROM input/selection precedence, atomic
   extraction handoff and all exit/error outcomes.
5. The display contract: 256x224 source, aspect-preserving integer scale,
   nearest-neighbor sampling and resize behavior. Presentation output must not
   alter canonical gameplay state.

## Acceptance

- A tracked command builds the desktop target reproducibly without global
  package installation; ROM-free debug/sanitizer CI and headless tests remain
  available when a display is absent.
- Authored tests exercise PAL scheduler boundaries with a fake clock, including
  no early update, exact deadline, bounded catch-up and long-stall recovery.
- Authored tests exercise keyboard/gamepad mask mapping, simultaneous and
  released inputs, disconnect/focus-loss clearing and two-port ownership where
  exposed. One input snapshot reaches exactly one simulation update.
- The app validates every Classic pack identity through the accepted native
  reader before gameplay. Missing-pack first launch exact-gates the supported
  ROM and creates the pack atomically; wrong/cancelled/missing input and corrupt
  pack fail clearly. A later launch passes with the ROM absent.
- The accepted 256x224 renderer is displayed with deterministic nearest-neighbor
  integer scaling; resize/display cadence changes do not alter the canonical
  state sequence for a frozen live-input script.
- Audio omission is explicit in tracked help/startup documentation and no audio
  success is claimed.
- Debug and sanitizer suites pass locally; macOS/Linux hosted CI is green;
  repository hygiene finds no ROM, extracted assets, generated packs, states or
  captures; a fresh independent reviewer approves the exact behavioral commit.
